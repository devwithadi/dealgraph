DealGraph · technical data flow

One request ID, one evidence chain, many review points

This code-shaped view follows a live run across the CLI, pipeline, sourcing, and analysis/reporting roles. It includes both source branches, provider boundaries, security controls, deterministic decisions, atomic persistence, and nonzero failure semantics.

Request identity

One validated ID crosses every boundary

  • bind_request_id() accepts only 1–128 safe characters and stores the value in a ContextVar.
  • HTTP calls carry X-Kong-Request-ID; Agent Reach inherits it through its fixed subprocess environment.
  • Bedrock request metadata, manifest.json, logs, and RunSummary retain the same value.

Provider boundary

Models are lazy and constrained

  • Configuration is validated before sourcing.
  • All model providers use LiteLLM, and Bedrock credentials resolve only when a model call runs.
  • OpenAI-compatible endpoints must be public HTTPS on port 443; credentials never enter artifacts.

Web trust boundary

Public evidence is treated as untrusted

  • SOURCE_REGISTRY is the allow-list; PitchBook is disabled and LinkedIn/Crunchbase are blocked.
  • SSRF controls validate public IPs on every redirect, obey robots.txt, accept HTML only, and cap response size.
  • Search quota failures become sanitized research gaps instead of repeated calls or hidden degradation.

Decision contract

Narrative generation cannot override the investment rubric

  • Screening output must map to known candidate slugs. Final synthesis must reference collected evidence IDs.
  • Runtime code validates the five closed score dimensions, recalculates the weighted score and recommendation, and computes confidence from evidence coverage—not model confidence.
  • Missing financial or team facts remain null or Unknown; first-party claims alone cannot produce high confidence.

Persistence + failure

Artifacts are the durable audit log

  • JSON writes are atomic: temporary file, then replace.
  • Outputs include input, candidates, screenings, evidence, analyses, shortlist, gaps, manifest, and one-page PDFs.
  • Per-company failure isolation keeps successful memos; any failure makes the CLI return nonzero.
